1. CHAPTER 1: EXECUTIVE SUMMARY & RESEARCH OVERVIEW
================================================================================
1.1 Background & Core Problem
As spatial computing and generative artificial intelligence converge, integrating 
AI-generated 3D assets into scanned physical environments (e.g., 3D Gaussian Splatting) 
traditionally encounters critical bottlenecks:
  - Severe hardware constraints and Out-Of-Memory (OOM) GPU kernel crashes.
  - Geometric visual artifacts such as Z-fighting, mesh clipping, and spatial occlusion.
  - Excessive reliance on latency-prone cloud infrastructure.

1.2 The Vectra Solution
Vectra bridges the gap between high-fidelity digital twins and localized generative 
AI pipelines without external cloud dependencies. It operates under a strict consumer 
edge hardware limit (8GB VRAM maximum threshold, targeting NVIDIA RTX 4060 GPUs).

Key Technical Breakthroughs:
1. Deep Splat Excavation (DBSE): A mathematical volumetric raycast masking algorithm 
   that dynamically overrides 3D Gaussian splat opacity values in fragment shaders 
   to cleanly excavate spatial volume for newly spawned generative assets without 
   permanently altering source point cloud files.
2. Sequential VRAM Orchestration: A strict memory recycling pipeline that executes 
   deep learning models sequentially (U2-Net background removal -> SDXL-Lightning / LCM 2D 
   latent generation -> TripoSR 3D mesh reconstruction) with PyTorch CUDA cache 
   purging between steps to prevent memory spillage.
3. Decoupled Hybrid Client-Server Architecture: A browser-based WebGL/Three.js viewport 
   communicating with an autonomous Python FastAPI engine through a resilient 
   VPS Proxy Gateway.

2.2 End-to-End Operational Workflows

WORKFLOW A: Spatial Point Cloud Scanning & Rendering
1. User drops a raw `.ply` or compressed `.ply.gz` spatial scan into the viewport.
2. JavaScript decompresses the GZIP payload in the browser using Native DecompressionStreams.
3. Custom hooks (`adjustSplatBufferScales`, `adjustSplatArrayScales`) intercept PlyParser.
4. Scale exponentiation multiplier (`window.VECTRA_SPLAT_SCALE = 0.05`) corrects bloated splats.
5. `SortWorker` (Web Worker) continuously sorts splats in background threads for 60 FPS WebGL rendering.

WORKFLOW B: "Extract Mode" (Deep Splat Excavation - DBSE)
1. User clicks `[EXTRACT MODE]` in viewport UI and draws a 2D bounding rectangle.
2. WebGL converts viewport 2D coordinates into 3D raycast frustum volume.
3. DBSE overrides opacity of intersecting splats to 0 in fragment shader (excavating void).
4. Viewport captures clean object image payload (base64 PNG) or URL.
5. POST request sent to `/api-proxy/api/extract`.
6. Proxy forwards request to Local GPU Engine (`/api/extract` on port 8001).
7. `main.py` processes image with U2-Net, crops bounds, pastes onto white canvas, feeds to TripoSR.
8. Generated 3D GLB mesh returned to client and anchored precisely inside excavated space.

WORKFLOW C: "Creator Mode" (Text-to-3D Summoning Protocol)
1. User enters text prompt (e.g. "cyberpunk katana") and clicks `[SUMMON]`.
2. Request dispatched to Proxy Gateway on port 8000 (`/summon`).
3. System enhances prompt: "A high-quality 3D asset of <prompt>, white background, orthographic projection, front view."
4. Proxy attempts Cloud 2D generation (Fal.ai SD3.5 or Replicate SD3).
5. If Cloud API fails or keys are unconfigured, Proxy seamlessly engages Local Fallback.
6. Local Fallback calls `main.py` port 8001 (`/api/summon`).
7. `LCM_Dreamshaper_v7` generates 256x256 orthographic 2D tensor in 2 inference steps (FP16).
8. `torch.cuda.empty_cache()` purges VRAM.
9. `rembg` removes background and centers image onto 512x512 white canvas.
10. `TripoSR` infers implicit 3D vector fields and extracts GLB mesh via marching cubes.
11. VRAM cleared again via `torch.cuda.empty_cache()`.
12. Binary GLB payload returned to client browser and placed in active 3D world space.

   - Entry portal featuring a 3D procedural cyberpunk city background canvas (`#bg-city`).

   - Navigation links to Demo (`/demo`), Presentation (`/presentation`), Source Code, Research Paper.

2. Spatial Core Viewport (`resources/views/welcome.blade.php`, `resources/js/app.js`):
   - Interactive 3D application canvas (`#vectra-canvas`).
   - Bento-grid telemetry overlays: GPU load, VRAM allocation (4.2GB / 8GB), temperature, grid drift.
   - Interactive control buttons: `[INJECT SPATIAL SCAN]`, `[Creator Mode]`, `[Extract Mode]`.
   - Dynamic HUDs for Extract Mode bounding box canvas (`#selection-canvas`) and loading progress.
   - Configuration Modal (`#creator-config-panel`) for dynamically setting API keys & engine URLs.

3. Scrollytelling Presentation (`resources/views/presentation.blade.php`, `resources/js/presentation.js`):
   - 16-stage scrollytelling deck showcasing the Master's thesis methodology.
   - Procedural WebGL Saturn gas giant with storm bands, concentric A/B/C ring divisions, Cassini gap.
   - 6,000 multi-colored additive stardust particles (`BufferGeometry`).
   - Post-processing pipeline using `EffectComposer`, `RenderPass`, and `UnrealBloomPass` (strength 1.8).
   - KaTeX integration for live rendering of LaTeX mathematical equations in scroll stages.

3.3 Key Frontend Features & Algorithms
- NoclipFlyingControls (in `resources/js/app.js`):
  Replaces standard OrbitControls with a first-person 6DoF noclip camera system. Supports WASD + QE (float up / sink down), Shift-key sprint, and right-click PointerLock mouse orientation.
- Custom Splat Scale Correction:
  Intercepts Gaussian Splats PlyParser (`parseToUncompressedSplatArray`, `parseToUncompressedSplatBuffer`). Applies exponential logarithm checking and `VECTRA_SPLAT_SCALE = 0.05` to fix bloated splat rendering.
- Web Worker Splat Sorting:
  Integrates `splat-sort.worker.js` via Vite worker imports to execute distance sorting in off-screen threads, keeping main UI thread smooth at 60 FPS.

4. CHAPTER 4: DEEP LEARNING & GPU AI BACKEND (SERVER LAYER)
================================================================================
4.1 Local GPU Engine (`main.py` - Port 8001)
The primary computational backend hosting PyTorch and neural models locally.

Core Setup & Environment:
- Thread Constraint: Enforces `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `torch.set_num_threads(1)` to avoid CPU thread contention.
- Device Selection: Automatically detects CUDA GPU (`cuda:0`, FP16) or CPU (FP32).

Loaded Models:
1. `rembg` (U2-Net):
   - Session initialized with `u2net` model on CUDA execution provider.
   - Used for fast, sharp background removal and foreground bounding box extraction.
2. `TripoSR` (Stability AI):
   - Model loaded via `TSR.from_pretrained("stabilityai/TripoSR")`.
   - Chunk size configured to `8192` for CUDA (or `1024` for CPU).
   - Accepts foreground image composited on solid white background (255, 255, 255) with 85% canvas fit.
   - Extracts 3D triplane scene codes and generates GLB mesh via marching cubes algorithm.
3. `LCM Dreamshaper v7` (Stable Diffusion T2I):
   - Loaded lazily (`load_t2i_pipeline()`) using `StableDiffusionPipeline` and `LCMScheduler`.
   - Generates 256x256 2D images in 2 inference steps with guidance scale 8.0 for rapid execution.

Endpoints:
- `POST /summon` & `POST /api/summon`: Full local Text-to-3D pipeline (LCM -> U2Net -> TripoSR -> GLB binary response).
- `POST /extract` & `POST /api/extract`: Image-to-3D pipeline (Base64/URL image -> U2Net -> TripoSR -> GLB binary response).
- `GET /api/config`: Returns local engine status and configuration flags.

Memory Guard (Sequential Orchestration):
```python
# Phase 1: Brain (T2I)
image = generate_image(req.prompt)
torch.cuda.empty_cache() # Purge VRAM

# Phase 2: Body (I23D)
mesh = generate_3d(image)
torch.cuda.empty_cache() # Clean up VRAM
```

5. CHAPTER 5: VPS PROXY GATEWAY & FALLBACK INFRASTRUCTURE
================================================================================
5.1 VPS Traffic Controller (`proxy_server.py` - Port 8000)
Acts as an intelligent router and fallback gateway between client requests and cloud/local AI workers.

Functionality:
- Environment Loading: Reads credentials from `.env` (`FAL_KEY`, `REPLICATE_API_TOKEN`, `LOCAL_ENGINE_URL`).
- Cloud Integration:
  - Fal.ai API: Calls `https://fal.run/fal-ai/stable-diffusion-v35-large` for SD3.5 Large 2D images.
  - Replicate API: Calls Replicate predictions endpoint (`version 528a60cd...`) for Stable Diffusion 3 with polling.
- Resilient Local Fallback:
  - If Cloud API keys are missing, invalid, or exhausted, automatically catches exceptions and falls back to Local Engine (`http://127.0.0.1:8001/api/summon`).
  - Sets long HTTP timeouts (up to 600s) to handle CPU/GPU mesh extrusion safely.
- Dynamic Reconfiguration (`POST /api/config`):
  - Allows live updates of `FAL_KEY`, `REPLICATE_API_TOKEN`, and `LOCAL_ENGINE_URL` directly from the web UI, rewriting `.env` safely.

9.1 Management Script Commands
Navigate to `/www/wwwroot/vectra.parsabe.com` in terminal:

1. Start all AI servers:
   `./start.sh`
   - Launches `main.py` on 127.0.0.1:8001 (GPU Engine)
   - Launches `proxy_server.py` on 0.0.0.0:8000 (VPS Proxy Gateway)

2. Check server status:
   `./status.sh`
   - Outputs running PID and active ports.

3. Stop all AI servers:
   `./stop.sh`
   - Kills PIDs recorded in `engine.pid` and `proxy.pid`.

4. Tail live server logs:
   `tail -f engine.log`
   `tail -f proxy.log`

9.2 Manual CLI 3D Mesh Generation
Run offline Text-to-3D generation directly via command line:
`/www/wwwroot/venv/bin/python main.py "cyberpunk helmet"`
- Output 2D PNG saved to: `output/output_<timestamp>.png`
- Output 3D GLB saved to: `output/output_<timestamp>.glb`

9.3 Troubleshooting & Hardware Verification
- Check CUDA Status:
  `nvidia-smi`
- Clear Stale PyTorch VRAM:
  `python3 -c "import torch; torch.cuda.empty_cache()"`
- Nginx Log Verification:
  `tail -n 50 /www/wwwlogs/vectra.parsabe.com.error.log`
